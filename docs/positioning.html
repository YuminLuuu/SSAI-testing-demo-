一个人的适应力

这份文档是为了让我们自己在做取舍时有个准绳，也是为了在跟资助方、学术合作方讲这件事时，能用他们听得懂的话讲清楚。它不是给用户看的——用户永远不该看到这里面任何一个词。

v0.1配套原型：台风前的一个人状态：假设，未验证
一句话
定位 通过补齐知识与社会连接这两项，提升低适应能力个体在极端天气事件中的适应能力（adaptive capacity）的工具。

这句话是能对着气候适应领域的人说的，而且经得起追问。它每一个词都有出处，下面逐一交代。

坐标

我们在哪张地图上

应对气候变化有两条腿：减缓（mitigation）处理原因，也就是减排；适应（adaptation）处理后果，也就是调整人和系统去承接已经发生和将要发生的气候影响。我们显然在适应这一侧。

但适应本身有层次——国家和城市层面是海绵城市、防洪工程、建筑规范；社区层面是绿化降温、避暑点、脆弱人群登记；家庭和个人层面才是储备、保险、房屋改造、以及知识与关系。我们在最后一层，而且是这一层里最"软"的两项。

我们同时踩在一个相邻领域上：防灾减灾（DRR, Disaster Risk Reduction）。它的经典周期是「预防 → 备灾 → 应急 → 恢复」，而原型的四段时间轴（T-72h / T-24h / 进行中 / 灾后）几乎就是这个周期的逐字翻译。

要能答上的追问 「你处理的是长期气候趋势，还是单次极端事件？」——诚实的答案是：目前是后者。我们做的是气候适应与防灾减灾重叠区里、个体层面的备灾工具。这两个领域在政策上早已融合，站在交叉点不是问题；假装自己已经覆盖了长期趋势才是问题。
机制

我们只动了一个变量

气候风险领域有一个通用的分解方式。把它逐项对照一遍，就能非常清楚地看到这个产品的作用边界在哪——以及它有多窄。

Hazard致灾因子——台风、暴雨、高温本身我们不改变

Exposure暴露度——你在不在受影响的地方基本不改变，只帮用户认清
×
Sensitivity敏感性——慢性病、行动不便、年龄我们不改变
+
Adaptive
Capacity适应能力——通常拆成经济资源、信息、技术、基础设施、制度、技能、社会资本七项。我们只动其中两项：技能／知识，和社会资本（求助渠道、报平安网络）。这是我们唯一在动的东西

把这件事说清楚有两个好处。对外：它让我们的表述可信，因为我们没有夸大。对内：任何一个不作用在"技能"或"社会资本"上的功能想法，都应该被放到很后面。这是一条能真正拒绝需求的判据。

产品观点

从 coping 走向 adaptation

这个领域会区分两个常被混用的词，而这个区分正好是我们产品观点的名字：

Coping · 应对

短期的、被动的。用手头现有的东西撑过这一次。撑过去了，什么也没留下。

Adaptation · 适应

长期的、前瞻的。改变自己的结构和能力，让下一次变得更容易。

最初的直觉是"很多人对极端天气的应对是滞后的，我们想做预防向"。那句话描述的正是从 coping 往 adaptation 移动。这是我们的立场，也直接给了我们一个比日活更合适的指标——见下。

原型里 T+ 阶段的最后一条「趁记忆还新，写下这次哪里最卡」，是整份清单里唯一一件对下一次有用的事。它在信息量上最轻，在定位上最重：它是这个产品从 coping 跨到 adaptation 的那一步。

人群

为什么是独居

选独居不是拍脑袋。独居在气候脆弱性文献里是被反复验证的风险因子。

最常被引用的是 Eric Klinenberg 对 1995 年芝加哥热浪的研究（《Heat Wave: A Social Autopsy of Disaster》）。那次热浪造成数百人死亡，他发现独居是最强的死亡风险因子之一。更关键的是：两个人口结构和贫困率高度相似的相邻街区，死亡率却相差很大，差别在于社会基础设施——街上有没有商铺、邻里认不认识、有没有人会来敲你的门。

这项研究几乎是在直接论证我们的两个核心假设：独居本身就是脆弱性变量，与收入无关；社会连接是可干预、且有效的适应能力。

对产品的直接含义 「报平安网络」和「该找谁 + 怎么开口」不是附加功能，它们是这个产品的核心机制。应对知识那一部分，市面上到处都有；社会连接这一部分，几乎没有人做。如果要砍功能，先砍知识，别砍关系。

当前的人群假设（未验证）

一线／新一线城市、25–35 岁、独居、租房、生活经验有限、社交求助成本高。选它的理由是执行性的：她能自己表达、自己传播、自己决定要不要装。不是因为她最脆弱——最脆弱的是独居老人和行动不便者，但那两个人群的产品形态完全不同（老人端的真实用户是异地子女）。这一点要一直记着，不要自我感动。

语言纪律

什么时候说气候适应，什么时候绝对不说

「气候适应」这个词对不同受众的价值天差地别。搞混了会同时失去两边。

受众用不用为什么
产品界面、给用户的一切文案绝对不用没有人会因为"气候适应型工具包"下载任何东西。她的语言是「台风天一个人在家好慌」「明天到底要不要去上班」。界面上出现这四个字，只会让她觉得这不是给她的。
资助方、公益组织、评委要用这是有资金、有政策议程、有国际框架（国家适应计划、仙台减灾框架）的领域。这套词汇是入场券和共同语言。
学术合作、数据来源方要用用 adaptive capacity 和 vulnerability 的框架描述，对方能立刻判断我们在做什么，也更容易开口要数据。
投资人看情况先讲人群和留存机制，气候框架只作为市场趋势的注脚。反过来讲会显得我们在做公益项目而不是产品。

一句话规则：对内用它指导设计和定义指标，对用户一个字都别提。

衡量

不要看日活

极端天气一年发生几次，日活对这个产品是一个有害的指标——它会逼我们往"每天来打开一下"的方向加功能，而那些功能一定和核心机制无关。

该看的它在验证什么
预警窗口内的完成率预警发布后 72 小时内，用户勾掉了几条。这是"外部事件替我们唤起动机"这个机制是否成立的直接证据。
跨事件的准备度提升同一个用户第二次台风时的准备度，是否高于第一次。这是 coping → adaptation 的唯一硬证据，也是这个产品存在的理由。
社会连接的建立率有多少人真的填了紧急联系人、真的发出了那条约定消息。这是最难但最有价值的一个数。
求助话术的使用复制率、以及"复制之后真的打了电话吗"。如果这块数据好，产品的重心就该整体挪过去。
证伪

什么会让我们停下来

这些不是风险清单，是预先写好的停止条件。写在前面，是为了到时候不会自己骗自己。

  1. 访谈里没有人在事后做过任何准备动作。那说明"预防"是伪需求，我们只能做事发工具，市场和价值都小很多，整个定位要推倒重来。
  2. 「该找谁 + 怎么开口」没有引起明显反应。那说明我们对这个人群的判断错了——她们卡住的地方不是社交成本，而是别的东西。这一块是我们最独特的假设，它塌了，差异化就塌了。
  3. 找不到官方之外的独家数据来源。没有超本地的积水点、停电范围、社区级信息，我们就只是一个套壳的内容产品，会被免费且权威的官方渠道碾过去。
  4. 个性化的四个问题产生的差异，用户感知不到。那"因人而异"这个核心卖点不成立，产品会退化成一份精美的通用清单。
当前状态

下一步不是加内容

原型（v0.1）已经跑通了：四段时间轴、四个个性化问题、动作卡的完整字段结构、求助话术模块。它不是用来验证"信息够不够全"的，而是用来验证三件事：按时间阶段而非知识分类组织，用户是否更容易照做；个性化产生的差异，用户是否感知得到；「该找谁」这一块是不是比应对知识本身更有价值。

接下来两周

  • 找 8–12 个过去 12 个月真实经历过台风或暴雨的独居者，只问回顾性行为，不问"你会不会用"。重点问：那天你具体做了什么、几点做的、搜了什么、问了谁、哪个时刻最不知所措、事后有没有为下次做任何准备。
  • 拿原型让他们边看边说：哪一条你真的会做，哪一条你看了就划过去。划过去的比勾选的更有信息量。
  • 看小红书／微博在台风周的自然内容和评论区提问——零成本的需求探针，同时它们也是竞品。
内容安全 原型里的具体数字与处置方法目前全部是待核对的草稿。在给任何真实用户使用之前，必须逐条比对应急管理部门、当地气象台、红十字会的公开指引，并标注来源。涉水深度、中暑判断、食物安全这几类写错了是会出事的。产品任何时候都不得与官方预警相矛盾，并始终提供官方渠道的出口。

参考框架：IPCC 关于 adaptation 与 vulnerability 的定义体系；仙台减灾框架（Sendai Framework for Disaster Risk Reduction）的备灾—应急—恢复周期；Eric Klinenberg,《Heat Wave: A Social Autopsy of Disaster in Chicago》(2002)。

另需留意「适应不良（maladaptation）」这一概念：某些措施短期有效但长期加剧脆弱性——最典型的是高温时人人猛开空调，加重电网负荷并加剧城市热岛。内容设计时应主动避开这类建议。
